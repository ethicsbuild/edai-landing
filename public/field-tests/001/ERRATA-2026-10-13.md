## 2. The baseline prompt, now fixed

Section 7 fixed the instruction's intent but not its exact words. They are fixed now:

- Model: `claude-haiku-4-5-20251001`, maximum 16 output tokens, default sampling settings.
- System text: "You will be given a passage and a proposition about it. Reply with the probability, between 0 and 1, that the proposition is true. Reply with the number only and nothing else."
- User text: "Passage:" followed by the item's state, a blank line, then "Proposition:" followed by the question.
- One request per item for the primary question, one for the paraphrase, and three repeats of the primary for jev-0000 through jev-0199: 4,600 requests.
- A reply that is not a single number between 0 and 1 is counted as missing. The number of missing replies is reported, and they are excluded from the statistics, never re-requested.

## 3. Harness details the protocol left open

The harness is published here as [run-ft001.cjs](run-ft001.cjs), SHA-256 42c9bf4658ddf25bbc0bc21e536f3a9d33b20dd3e6587f57b2b6a85395b30497. It will not change before or during the run. It fixes these details:

- **Order:** the 2,000 main requests in id order, then three repeat rounds over jev-0000 through jev-0199, each round in id order.
- **Request ids:** the three questions are sent under the ids `primary`, `paraphrase` and `choice`. TypeSafe's documentation says question ids are not sent to the model.
- **Party labels** for the EQUAL questions are read from the item's own state line (Petitioner/Respondent or Appellant/Appellee), never from the labeled file.
- **Pause:** a fixed 250 milliseconds between requests.
- **Retries:** network errors, timeouts (60 seconds), HTTP 429 and HTTP 5xx are retried up to 3 times, waiting 2, 4 and 8 seconds. Every attempt is logged. Any other error stops the run, and the run resumes from where it stopped. A successful request is never sent again.
- **Blindness:** the harness never opens `items_labeled.jsonl`. The answer key is not read until analysis.
